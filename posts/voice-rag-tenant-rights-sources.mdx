> **TL;DR:** A voice answer has no footnotes, so a voice RAG agent needs a second channel for its evidence. Retrieve inside `on_user_turn_completed`, inject the passages into that turn only, publish the top section to the screen, and treat "nothing cleared the floor" as a first-class outcome that clears the citation. The floor is a property of your embedding model, so measure it again every time you change models.

A chatbot can paste a link under its answer. A voice agent cannot. It speaks two sentences and the caller has no way to tell whether those sentences came from your documents or from the model's general idea of how renting works.

For most voice RAG demos that is fine. For anything near legal, medical or financial territory it is the whole problem. The tenant rights agent in [awesome-voice-apps](https://github.com/mahimairaja/awesome-voice-apps/tree/b881d6b864b45af1e5252e2e304877e47cf2d29b/demos/tenant-rights) answers US renter questions from a short document of HUD-based guidance, and its interesting part is not the retrieval. It is what the agent does with the evidence, and what it does when there is none.

## Retrieval belongs in the turn, not in a tool

The common way to add RAG to a LiveKit agent is a `lookup_docs` function tool. The model decides when to call it. That costs an extra LLM round trip on every grounded answer, and in voice an extra round trip is roughly the gap between "snappy" and "is it still there?".

This agent retrieves on every completed user turn instead, before the model runs:

```python
class RentersGuide(Agent):
    async def on_user_turn_completed(self, turn_ctx: ChatContext, new_message: ChatMessage) -> None:
        question = (new_message.text_content or "").strip()
        if not question:
            _unmount_card(self._room)
            raise StopResponse()

        query_vec = await embed_query(question)
        result = retrieve(self._index, query_vec, k=3, floor=self._floor)

        if result.covered:
            passages = "\n\n".join(
                f"[Source: {hit.source_label}]\n{hit.text}" for hit in result.hits
            )
            turn_ctx.add_message(role="assistant", content="System note: ... \n\n" + passages)
            ...
```

(The error handling and the full system notes are trimmed here; the linked source has them.)

One embedding call per turn, then one LLM call. The cost is that greetings and "thanks" also get embedded. With a small embedding model that is a fraction of a cent per thousand turns, and it buys a deterministic answer to "did we have evidence for this turn?".

Two LiveKit details make this pattern safe. `StopResponse` on an empty transcript means a cough or a garbled STT result never produces an ungrounded reply. And `turn_ctx` is a copy: in LiveKit Agents 1.8 the session builds it from `self._agent.chat_ctx.copy()` and passes it to the reply for that turn only. The three passages go to the model once and do not pile up in the history, so a two-minute call does not drag every earlier citation along with it.

## The floor is the product decision

`retrieve` is twenty lines of numpy: cosine similarity against an in-memory matrix, top k, and one extra field.

```python
best = hits[0].score
return RetrieveResult(hits=hits, covered=best >= floor, best_score=best)
```

`covered` is the line between "I am reading from the guidance" and "I am telling you what is generally true". Everything downstream branches on it: what the model is told, and what the screen shows.

The floor depends on the embedding model, and it is not portable. The contributed demo runs on NVIDIA NIM's `nv-embedqa-e5-v5` with a floor of 0.33, tuned so real renter questions (about 0.38 and up on that model) clear it and small talk (about 0.25) does not. When we moved the hosted copy to OpenAI's `text-embedding-3-small`, I measured again against the same eight sections:

| Utterance | Closest section | Cosine |
|---|---|---|
| Can my landlord come into my apartment without telling me? | Landlord entry and notice | 0.56 |
| How long does my landlord have to return my security deposit? | Security deposits | 0.55 |
| Can they evict me without going to court? | Eviction basics and notice | 0.54 |
| I use a wheelchair, can I ask for a ramp? | Reasonable accommodations and modifications | 0.45 |
| They won't rent to me because I have kids | Fair housing and discrimination protections | 0.32 |
| how are you doing today | (below the floor) | 0.17 |
| hi there | (below the floor) | 0.14 |
| tell me a joke | (below the floor) | 0.10 |

On this model the hosted copy uses 0.25. The weakest real question I tried scored 0.32 (familial status phrased casually, with no word from the section title), and the chattiest off-topic line scored 0.17. Keeping the old 0.33 would have quietly thrown away the "kids" question, which is exactly the kind of fair housing question the guidance exists for.

That is my main take from this demo: **an embedding swap is a behaviour change, not a dependency bump.** Same documents, same questions, different score distribution. If your floor lives in a constant nobody re-measures, the swap ships a different product.

The same run also showed what a floor cannot do. "My landlord raised the rent by 30 percent, is that legal?" scored 0.398 against "Landlord entry and notice", comfortably above any floor that keeps the "kids" question. The guidance has no rent section; the two just share the word landlord. No threshold separates that false hit from a weak true one. The fixes live elsewhere: a reranker, a section on the topic, or an explicit list of what the documents do not cover.

Two practical notes. Keep the measurement as data next to the floor (the hosted adapter's comment records the ranges and the date). And pick misses over false hits: here a miss means the agent answers generally and shows no card, while a false hit puts the wrong section on screen with an authoritative-looking label.

## A stale citation is worse than none

When a turn is covered, the agent publishes the top section to the page over the LiveKit data channel. When it is not covered, it removes the card:

```python
def _unmount_card(room: rtc.Room) -> None:
    mounted = getattr(room, "_ui_mounted", None)
    if not mounted or CARD_ID not in mounted:
        return
    mounted.discard(CARD_ID)
    publish_ui_event(room, "Card", "unmount", component_id=CARD_ID)
```

This is the detail I would copy into any client agent. If the caller asks about deposits, then asks "what about rent increases?" (which this guidance does not cover), the screen must not keep showing the deposit section next to an answer about rent. Leaving it up would make an uncovered answer look sourced.

The card names the section and the document separately (`title` is the heading, `subtitle` the source label), so the caller sees "Security deposits, from HUD's resident rights and responsibilities guidance" rather than a vague "from our documents".

Two more pieces make the screen honest:

- **The topic list is derived from the index.** `_publish_static_ui` mounts a list built from the indexed section headings, so the agent never advertises a topic it cannot retrieve. Add a document, rebuild the index, and the menu updates with it.
- **Metadata stays out of the index.** The builder chunks the markdown on `##` headings and skips "Where to get help". That section's text is already in the agent's redirect path, and indexing it would let an out-of-scope question match "get help" above the floor and be answered as if it were covered.

One honest caveat. The prompt lets the model add "well-established general knowledge" on top of the passages, and give the common rule when a number varies by state. That makes the agent useful, and it means the card shows the passage the answer leans on, not proof that every word came from it. The guidance itself deliberately avoids statute numbers and deadlines, and the prompt forbids stating them as certain, which is what keeps that trade acceptable here. For a client in a regulated domain I would tighten it: grounded answers only when covered, and a scripted redirect when not.

## What changed to host it

The contributed demo runs entirely on NVIDIA: Riva STT, a NIM LLM, Riva TTS and NIM embeddings, all on one `NVIDIA_API_KEY`. Our playground meters cost per call and only knows Deepgram, OpenAI and Cartesia prices, and unknown pricing ends a call. So the hosted copy keeps the agent class, prompts, retrieval and UI events, and swaps two things around them.

The voice stack comes from the shared playground guard, the same wrapper every cascaded demo uses. The embeddings come from a small adapter that replaces one function the agent looks up at call time:

```python
class TenantGuide(_module.RentersGuide):
    def __init__(self, room) -> None:
        super().__init__(room, _unindexed(), FLOOR)
        from openai import AsyncOpenAI

        self._embeddings = AsyncOpenAI(max_retries=0, timeout=5)

    async def embed_question(self, text: str) -> list[float]:
        vectors, tokens = await embed(self._embeddings, [text])
        self.meter_embedding(tokens)
        return vectors[0]
```

Three decisions in there are worth explaining.

**One client per call.** The worker runs calls as threads, and in LiveKit Agents each thread job runs its own event loop. An `AsyncOpenAI` client cached at module level, which is fine in the contributed single-process demo, would be shared across those loops. The hosted copy creates the client per call and finds the right one through a context variable set for the turn.

**Embeddings are billed to the caller.** VoiceGateway meters the STT, LLM and TTS calls it sees, but a direct embeddings call goes around it. The hosted agent reads `usage.total_tokens` from each response and adds it to the call's ledger at OpenAI's published $0.02 per million tokens. It rounds to nothing, and it is still the right habit: a cost you do not attribute is a cost nobody caps.

**The index is built once per worker.** The demo's offline builder writes `data/index.npz`, which is gitignored because it depends on the operator's key and model. The hosted worker embeds the eight sections (a few thousand tokens) on the first call and reuses the matrix after that. If OpenAI is unreachable, the call still runs with the topic list and no citations, and the next call tries again.

## Testing the boundary

The contributed demo ships `test_rag.py`, which pins the grounding boundary with a fake three-vector index: a matching query clears the floor, an orthogonal one does not, and an empty index is never covered. No model, no network.

The hosted tests add the screen to that boundary. They build the index from the real guidance with fake one-hot vectors, run a covered turn and an uncovered one through the agent, and assert the exact UI traffic: a mount titled "Security deposits", then an unmount, plus two embedding charges on the call's ledger. The floor itself is not unit-testable in a meaningful way, because it depends on a real model. That measurement is a script you rerun when you change models, and its result belongs in the commit that changes the number.

## What this means for you

1. **Give every voice RAG answer a second channel.** A screen card, an SMS, a follow-up email: somewhere the caller can see what the answer came from. Then make sure it clears on turns with no source.
2. **Re-measure your floor whenever you change embedding models.** Run your real questions and your real small talk through the new model and write the ranges next to the constant.
3. **Bill every model call to the session that caused it,** including the ones your observability layer cannot see. Embeddings, rerankers and moderation calls are the usual blind spots.

The [tenant rights source](https://github.com/mahimairaja/awesome-voice-apps/tree/b881d6b864b45af1e5252e2e304877e47cf2d29b/demos/tenant-rights) runs with `uv sync`, `uv run python build_index.py` and `uv run python agent.py console` once you add an NVIDIA key and LiveKit keys. The [LiveKit RAG guide](https://docs.livekit.io/agents/logic/external-data/) covers `on_user_turn_completed` and other ways to inject context. The guidance text is a plain-language summary drawn from [HUD's renter resources](https://www.hud.gov/states/district_of_columbia/renting/tenantrights), and like the agent, it is information, not legal advice.

When we review a voice agent that answers from documents, the floor and the miss path are two of the first things we test, because they decide what the agent says when it does not know. If you are about to ship one, start a [production readiness review](/contact).
